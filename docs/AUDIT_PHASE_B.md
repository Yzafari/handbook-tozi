# گزارش ممیزی مرحلهٔ B — دیتاسنتر، جستجو، آفلاین و ماژولار بودن

تاریخ ممیزی: 2026-11-15  
مبنای مقایسه: بستهٔ `handbook-distribution-phase-a.zip`  
نسخهٔ ممیزی‌شده: همین پوشهٔ پروژه، پیش از بسته‌بندی Phase B

## 1. دامنه و تغییرات

در مقایسه با Phase A:

- ۱۱۰ فایل جدید اضافه شد.
- ۴۸ فایل موجود اصلاح شد.
- هیچ فایل قبلی حذف نشد.
- تعداد فایل‌های منبع/مستندات بسته، پیش از حذف فایل‌های محیطی، ۲۷۲ فایل است.

تغییرات اصلی:

1. سرویس مستقل ذخیره‌سازی فایل با احراز هویت داخلی، لینک کوتاه‌عمر HMAC، پشتیبانی Range و تأیید SHA-256 قبل از commit.
2. پردازش PDF و تصویر در Workerهای جدا، استخراج متن، OCR، قطعه‌بندی صفحه‌ای، نگهداری شماره صفحه و retry کنترل‌شده.
3. OpenSearch با جستجوی عبارت دقیق، جستجوی متنی/fuzzy، فیلتر دسترسی، Cursor، cache و حذف قطعات قدیمی پس از موفقیت bulk indexing.
4. صفحهٔ مدیریت دیتاسنتر برای بارگذاری، وضعیت ایندکس، صف OCR، reindex، حذف نرم، بازیابی و نمایش شاخص‌های حجم/پردازش.
5. فیلتر دسترسی جستجو بر اساس عمومی، مالک سند، سمت شغلی و نقش مدیر؛ کنترل دسترسی در PostgreSQL نیز دوباره بررسی می‌شود.
6. API نسخه‌دار، Health endpoint و قراردادهای عمومی ماژول‌ها.
7. صف آفلاین موبایل، SQLite/SQLCipher، SecureStore، همگام‌سازی Outbox و ارسال خودکار صف OCR پس از بازگشت اینترنت.
8. رجیستری ماژول‌های موبایل و بک‌اند، جلوگیری از شناسه و مسیر تکراری و تست‌های مستقل.
9. تنظیمات زبان فارسی/کوردی/انگلیسی، جهت RTL/LTR، پوسته روشن/تیره/سیستم/خودکار ساعتی و ذخیره محلی تنظیمات.
10. اسکریپت‌های ورود گروهی اسناد، reindex، backup و restore، نمونه Nginx و ظرفیت‌سنجی اولیه.

## 2. نتایج آزمون‌های اجراشده

| آزمون | نتیجه |
|---|---:|
| تست‌های Backend و DataCenter | ۳۳ موفق، صفر ناموفق |
| تست‌های رجیستری موبایل | ۳ موفق، صفر ناموفق |
| بررسی Syntax بک‌اند | ۱۰۰ فایل، بدون خطا |
| بررسی importهای نسبی بک‌اند | ۲۲۹ ارجاع resolve شد |
| بررسی Syntax فایل‌های JS/JSX/TS/TSX موبایل و پنل | ۹۳ فایل، بدون خطای نحوی |
| اعتبارسنجی YAML فایل Compose | موفق |
| اعتبارسنجی JSON فایل‌های package/app config | موفق |
| بررسی Syntax اسکریپت‌های Backup/Restore | موفق |
| بررسی Syntax سرور DataCenter | موفق |
| آزمون دستی SQL محلی SQLite | ایجاد جدول‌ها، نسخهٔ schema و ذخیرهٔ محلی تنظیمات/محاسبه موفق |

تست‌های OpenSearch با HTTP mock انجام شده‌اند؛ این تست‌ها ساخت bulk، قطعه‌بندی صفحه، فیلتر دسترسی، Cursor و عدم حذف دادهٔ قبلی هنگام شکست bulk را بررسی می‌کنند، اما جایگزین اجرای یک OpenSearch واقعی نیستند.

## 3. کنترل‌های مهم امنیت و پایداری

- هیچ فایل `.env` واقعی یا کلید خصوصی در بستهٔ تحویلی قرار نمی‌گیرد.
- بارگذاری فایل با اندازهٔ محدود، بررسی MIME/امضای فایل و SHA-256 انجام می‌شود.
- فایل‌های دریافت‌شده در Worker دوباره به‌صورت streaming از نظر اندازه و SHA-256 کنترل می‌شوند؛ فایل ناقص در صورت خطا پاک می‌شود.
- لینک مستقیم فایل کوتاه‌عمر است؛ نمونهٔ Nginx در access log مقدار URI را بدون query ثبت می‌کند تا token امضاشده وارد access log نشود.
- عملیات سنگین OCR و index خارج از مسیر پاسخ Search API انجام می‌شود.
- خرابی OpenSearch یا Storage نباید به‌تنهایی readiness کل API و ماژول‌های مستقل را از مدار خارج کند.
- Redis cache است و منبع حقیقت داده نیست.
- SQLite محلی رمزگذاری‌شده است و صف Outbox/ OCR در قطع اینترنت حفظ می‌شود.
- Migrationها افزایشی‌اند؛ قبل از اجرای آن‌ها روی دیتابیس واقعی باید Backup و آزمون روی Clone انجام شود.

## 4. محدودیت‌های تأییدنشده — مواردی که عمداً موفق اعلام نمی‌شوند

این محیط به زیرساخت واقعی پروژه متصل نبود؛ بنابراین موارد زیر هنوز تأیید عملیاتی نشده‌اند:

1. `prisma validate` و اجرای Migrationها روی PostgreSQL واقعی انجام نشده است؛ Prisma CLI/وابستگی کامل در محیط حاضر آماده نشد.
2. API و پنل با دیتابیس واقعی بالا نیامدند؛ Build و تست Vitest پنل اجرا نشد، چون نصب وابستگی‌ها در محیط با timeout مواجه شد. فقط Syntax فایل‌های پنل بررسی شد.
3. Expo prebuild، Android APK/AAB و iOS build اجرا نشده‌اند؛ وابستگی‌های native، Android SDK/Xcode و حساب انتشار در دسترس نبودند. برای موبایل هنوز package-lock تولید/تأیید نشده است.
4. Docker imageها build و اجرا نشدند؛ Compose از نظر YAML بررسی شد، نه از نظر اجرای container.
5. OpenSearch و Redis واقعی متصل نشدند؛ latency واقعی، heap، shard و throughput سنجیده نشده است.
6. دیتاست واقعی ۲۰ گیگابایتی در اختیار این مرحله نبود؛ ورود کامل، OCR حجیم، زمان ایندکس، نسبت رشد index و آزمون بار ۱۰ هزار کاربر انجام نشده است.
7. سرورهای Production، DNS، گواهی TLS، کلیدهای امن، مقصد Backup و حساب‌های سرویس‌دهنده هنوز به محیط متصل نیستند.
8. OCR فارسی و انگلیسی در کد پشتیبانی شده است. پشتیبانی OCR از کردی سورانی با مدل واقعی تأیید نشده؛ مدل `kmr` الزاماً معادل سورانی نیست و برای آن باید traineddata مناسب تأمین و آزمون شود.

## 5. قابلیت‌هایی که هنوز نباید آماده/فعال تلقی شوند

- محاسبات مهندسی تخصصی تا دریافت فرمول‌ها، ضرایب، منبع و شماره صفحهٔ تأییدشده فعال نمی‌شوند.
- محاسبه قبض تا دریافت فرمول و تعرفهٔ نهایی شما فعال نمی‌شود؛ پیش‌نویس ۱۴۰۴ مبنای محاسبهٔ قطعی نیست.
- پرداخت قبض از پرداخت اشتراک موجود جداست و اتصال عملیاتی آن به سرویس/درگاه مربوط تکمیل نشده است.
- OTP پیامکی به ارائه‌دهنده و اعتبارنامهٔ واقعی نیاز دارد.
- گفت‌وگوی همکاران، پیام‌های ایمنی، مناقصات، بازار تجهیزات و فرم‌های سازمانی هنوز ماژول‌های کامل و آماده انتشار نیستند.
- OCR و جستجوی دیتاسنتر زیرساخت و مسیر عملیاتی دارند، اما بدون دیتاست واقعی و آزمون Production تأیید نهایی کارایی ندارند.

## 6. شروط عبور به انتشار آزمایشی

1. اجرای `npm ci` در محیط توسعهٔ متصل و اجرای `npm test`، `npm run check`، `npm run prisma:validate` و Build پنل.
2. اجرای Migration روی Clone دیتابیس واقعی، تطبیق تعداد رکوردها و بررسی مبلغ/واحد پرداخت‌های قدیمی؛ مبلغ‌های قدیمی نامعلوم نباید حدس زده یا در درآمد قطعی جمع شوند.
3. اجرای Docker Compose در محیط ایزوله و آزمون اتصال Worker به PostgreSQL، Storage، Redis و OpenSearch.
4. ورود نمونهٔ واقعی اسناد، تطبیق checksum و بررسی نتایج جستجو با صفحهٔ مرجع PDF.
5. اجرای k6 با ۱۰۰، ۲۵۰ و ۵۰۰ کاربر هم‌زمان و ثبت p50/p95/p99، نرخ خطا و مصرف منابع؛ هدف p95 زیر ۱٫۵ ثانیه فقط پس از این آزمون قابل تأیید است.
6. آزمون قطع شبکهٔ موبایل، بستن اجباری برنامه، بازگشایی، همگام‌سازی و بازیابی دادهٔ محلی.
7. آزمون بازیابی Backup دیتابیس و Storage در میزبان جداگانه.
8. تکمیل فرمول‌ها/تعرفه‌ها و اتصال سرویس‌های بیرونی پیش از فعال‌سازی ماژول‌های وابسته.

## جمع‌بندی ممیزی

زیرساخت کدنویسی مرحلهٔ B و تست‌های قابل اجرا در این محیط موفق بوده‌اند؛ اما این گزارش به معنی تأیید Production، تأیید سرعت دیتاست ۲۰ گیگابایتی یا آماده‌بودن تمام ماژول‌های محصول نیست. انتشار واقعی فقط پس از عبور از شروط بخش ۶ مجاز است.
