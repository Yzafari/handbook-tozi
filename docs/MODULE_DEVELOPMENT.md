# افزودن ماژول جدید بدون تغییر هسته

## قرارداد اجباری ماژول

هر ماژول جدید در `backend/src/modules/<module-name>/` قرار می‌گیرد و حداقل این فایل‌ها را دارد:

```text
<module-name>/
├── module.json
├── index.js
├── <module-name>.routes.js
├── <module-name>.controller.js
├── <module-name>.service.js
├── <module-name>.repository.js
├── <module-name>.schema.js
├── sync-adapter.js (فقط برای دادهٔ آفلاین)
└── <module-name>.test.js
```

`module.json` مشخصات، وضعیت فعال‌بودن و نیازمندی‌های بیرونی ماژول را اعلام می‌کند؛ فیلد `requires` قرارداد/مستندات نیازمندی است و به‌تنهایی نصب یا در دسترس‌بودن سرویس بیرونی را تضمین نمی‌کند. وضعیت سرویس‌های حیاتی با Health و خطای اختصاصی همان ماژول کنترل می‌شود؛ خرابی Search نباید ماژول‌های مستقل را از مدار خارج کند. `module.json` همچنین `index.js` فقط Router را export می‌کند:

`module.json`:

```json
{
  "enabled": true,
  "name": "example",
  "version": "1.0.0",
  "basePath": "/example",
  "dependencies": [],
  "requires": ["auth", "postgresql"],
  "syncEntities": ["ExampleRecord"]
}
```

`index.js`:

```js
import router from './example.routes.js';
export default router;
```

برای ماژول آفلاین، `sync-adapter.js` نیز باید validator نوع داده را export کند؛ کلید validator باید دقیقاً با مقدار `syncEntities` برابر باشد. در ماژول آنلاین، `syncEntities` را حذف کنید.

رجیستری در زمان راه‌اندازی، ابتدا فقط `module.json`ها را می‌خواند و تنها برای manifestهای دارای `enabled: true` فایل اجرایی `index.js` را import می‌کند؛ بنابراین کد ماژول غیرفعال اصلاً اجرا نمی‌شود. وابستگی‌های ماژولی به‌صورت گرافی مرتب می‌شوند؛ وابستگی مفقود، مسیر تکراری، نام نامعتبر یا چرخهٔ وابستگی باعث توقف راه‌اندازی می‌شود، نه رفتار ناقص و خاموش.

## قواعد مرزبندی

1. یک ماژول فقط از API عمومی ماژول دیگر استفاده می‌کند؛ وارد پوشهٔ داخلی آن نمی‌شود.
2. منطق کسب‌وکار در Service است؛ Controller فقط ورودی/خروجی HTTP را مدیریت می‌کند.
3. دسترسی به Prisma از Repository یا Service همان ماژول انجام می‌شود.
4. هر مسیر باید اعتبارسنجی Zod، احراز هویت/مجوز مناسب و محدودیت نرخ داشته باشد.
5. هر تغییر دیتابیس باید Migration افزایشی و قابل بازگشت داشته باشد؛ حذف یا تغییر مخرب ستون بدون برنامهٔ مهاجرت ممنوع است.
6. تغییر API ناسازگار فقط در نسخهٔ جدید انجام می‌شود؛ مسیرهای قبلی تا پایان مهاجرت مصرف‌کنندگان حفظ می‌شوند.
7. ارتباط ماژول‌ها از طریق قرارداد عمومی، رویداد یا سرویس مشترک انجام می‌شود؛ import داخلی مستقیم ممنوع است.
8. اگر ماژول دادهٔ آفلاین دارد، نوع رکورد را در `syncEntities` در `module.json` معرفی و اعتبارسنجی payload آن را در `sync-adapter.js` export می‌کند؛ Sync Service بدون تغییر مرکزی، adapter را ثبت می‌کند.
9. هیچ ماژولی نباید در مسیر پاسخ فوری، OCR، پردازش PDF یا کار سنگین اجرا کند؛ کارهای سنگین به Worker منتقل می‌شوند.
10. دادهٔ محلی و صف همگام‌سازی باید در صورت قطع اینترنت حفظ شوند؛ عملیات نوشتن باید idempotent باشد.
11. فعال‌سازی ماژول جدید تا عبور تست‌های واحد، API، مجوزها، Migration و رگرسیون ممنوع است.

## ترتیب کنترل‌شدهٔ انتشار

1. ایجاد ماژول و manifest غیرفعال.
2. افزودن قرارداد API و Migration.
3. نوشتن تست‌ها و اجرای `npm run check` و `npm test`.
4. اجرای Migration روی دیتابیس آزمایشی و تست یکپارچگی.
5. فعال‌کردن `enabled: true` در نسخهٔ انتشار.
6. انتشار پشت Feature Flag در صورت وجود UI یا دادهٔ جدید.
7. پایش خطا، زمان پاسخ و نرخ موفقیت؛ در صورت مشکل، Feature Flag خاموش یا نسخهٔ قبلی بازگردانده می‌شود.

## تست‌های لازم قبل از ادغام

- ورودی معتبر و نامعتبر
- کاربر مهمان، کاربر عادی، نقش شغلی مجاز/غیرمجاز و مدیر
- دسترسی به دادهٔ متعلق به کاربر دیگر
- تکرار درخواست و idempotency
- قطع شبکه و تکرار همگام‌سازی، در صورت پشتیبانی آفلاین
- تعارض نسخه و حذف هم‌زمان
- Migration از نسخهٔ قبلی و بازیابی Backup
- تست رگرسیون ماژول‌های وابسته

## افزودن ماژول موبایل

1. صفحهٔ ماژول را به‌صورت Route مستقل در `mobile/src/app/` بسازید؛ Expo Router مسیر را خودکار ثبت می‌کند.
2. مشخصات نمایشی آن را در `mobile/src/core/modules/registry.js` ثبت کنید؛ صفحهٔ Home مستقیماً تغییر نمی‌کند.
3. `id` و `route` باید یکتا باشند. ماژول با `status: active` بدون Route معتبر پذیرفته نمی‌شود.
4. اگر دادهٔ ماژول باید آفلاین باشد، Repository آن از SQLite و Outbox استفاده کند و قرارداد Sync سمت سرور را نیز در manifest ماژول ثبت کند.
5. تست رجیستری و تست صفحه/منطق ماژول را اضافه کنید؛ سپس تست رگرسیون کل موبایل اجرا شود.
