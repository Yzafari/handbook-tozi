# ممیزی و رفع ایرادها — نسخهٔ سوم

**تاریخ:** ۵ آذر ۱۴۰۵ (۲۶ نوامبر ۲۰۲۶)
**دامنه:** مخزن `handbook-tozi` — موبایل Expo، API بک‌اند Express/Prisma، Docker Compose و گردش‌کار ساخت APK.

## ۱. یافته‌های مسدودکننده و اصلاحات

### ساخت و اجرای بک‌اند

| یافته | اثر | اصلاح |
|---|---|---|
| `prisma` در `devDependencies` بود ولی `backend/Dockerfile` با `npm ci --omit=dev` نصب می‌کند و بعد `npx prisma generate` اجرا می‌شد. | ساخت ایمیج بک‌اند شکست می‌خورد؛ در نتیجه API بالا نمی‌آمد و ورود/داده‌ها کار نمی‌کرد. | `prisma` به `dependencies` منتقل شد و `package-lock.json` بازتولید شد. |
| `docker-compose.yml` به‌صورت پیش‌فرض `NODE_ENV=production` می‌داد ولی متغیرهای الزامی اعتبارسنجی (`COOKIE_SECURE`, `COOKIE_SAME_SITE`, `OPENSEARCH_USERNAME/PASSWORD`, `REDIS_URL`, `DATACENTER_INTERNAL_TOKEN`, `DATACENTER_PUBLIC_URL`, `APP_BASE_URL`) را پاس نمی‌داد. | کانتینر در startup با «Invalid environment configuration» خارج می‌شد. | پیش‌فرض Compose به `development` تغییر کرد و همهٔ متغیرها با مقادیر قابل‌تنظیم پاس داده می‌شوند؛ `.env.example` تکمیل شد. |
| کوکی refresh با `NODE_ENV` کنترل می‌شد، نه با `COOKIE_SECURE` معتبرشده. | در استقرار پشت TLS با NODE_ENV غیر production رفتار کوکی ناسازگار بود. | تنظیم کوکی به `env.COOKIE_SECURE` متصل شد. |
| خطای اعتبارسنجی فقط `Validation error` برمی‌گرداند. | پیام قابل‌فهم فارسی به کاربر نمی‌رسید. | نخستین پیام Zod به‌عنوان `message` برگردانده می‌شود و فهرست کامل در `details` می‌ماند. |
| ثبت‌نام موبایل توکن برنمی‌گرداند. | پس از ثبت‌نام، کاربر بدون نشست می‌ماند. | ثبت‌نام نسخهٔ v1 بلافاصله نشست (access/refresh token) صادر می‌کند. |

### موبایل

| یافته | اثر | اصلاح |
|---|---|---|
| `ThemeProvider` در ریشهٔ اپ mount نشده بود. | صفحهٔ ابزارهای فنی و هر صفحهٔ دارای `useTheme` هنگام باز شدن crash می‌کرد. | `ThemeProvider` به `_layout.tsx` اضافه شد. |
| `global.css` در ریشه import نشده بود، در حالی که Metro با `withNativeWind` تنظیم شده است. | استایل `className` در صفحات فنی اعمال نمی‌شد. | import در `_layout.tsx` اضافه شد. |
| قراردادن مسیر `/tools/[id]` و `/tools/history` وجود نداشت؛ صفحهٔ ابزارها هم به مسیرهای ناموجود push می‌کرد. | «محاسبات فنی» باز می‌شد ولی هر ابزار خطا/صفحهٔ خالی می‌داد. | مسیرهای `technical-tools`, `tools/[id]` و `tools/history` ساخته شد و ابزارهای موجود به صفحهٔ خودشان نگاشت شدند. |
| `civil.pole-codes` به فایل خالی و `economic/unit-converter` فاقد اکسپورت بود. | import شکسته و typecheck خطا. | فایل‌های خالی و بی‌استفاده حذف شدند؛ ابزار بدون داده همچنان «در حال توسعه» است و باز نمی‌شود. |
| همهٔ ماژول‌های خانه `coming-soon` بودند و کارت‌های گفتگو، فرصت‌ها و معاونت‌ها فقط `View` بدون ناوبری بودند. | تب‌های خواسته‌شده در عمل غیرفعال بودند. | رجیستری همهٔ ماژول‌ها فعال شد و صفحات مستقل برای هرکدام ساخته شد. |
| صفحهٔ ثبت‌نام وجود نداشت. | امکان ساخت حساب نبود. | `signup.tsx` با اعتبارسنجی همراستا با بک‌اند و ورود خودکار اضافه شد. |
| خطای شبکه در ورود به‌صورت «اطلاعات را بررسی کنید» نمایش داده می‌شد. | تفاوت خطای شبکه و خطای حساب مشخص نبود. | `apiErrorMessage` اضافه شد و خطاهای شبکه/Timeout/HTTP را تفکیک می‌کند. |
| RTL سیستمی گوشی فارسی، چیدمان صریح RTL اپ را دوباره آینه می‌کرد (مثلاً لوگو سمت چپ). | چیدمان بین دستگاه‌ها ناسازگار بود. | `I18nManager.allowRTL(false)` و `forceRTL(false)` در ریشه؛ جهت هر صفحه فقط از زبان تنظیمات با `row-reverse`/`textAlign`. |
| تب‌های ماشین‌حساب انگلیسی و محاسبهٔ DEG در پیش‌نمایش و دکمهٔ محاسبه متفاوت بود. | نتیجهٔ پیش‌نمایش با نتیجهٔ نهایی یکی نبود. | برچسب‌های فارسی تب‌ها و یک تابع مشترک `toRadians` برای پیش‌نمایش، محاسبه و نمودار. |

## ۲. قابلیت تست اتصال

دکمه و کارت «تست اتصال» در تنظیمات، صفحهٔ ورود و مسیر `/connection-test` اضافه شد. کارت موارد زیر را نشان می‌دهد:

- آدرس واقعی API که همین نصب استفاده می‌کند (`EXPO_PUBLIC_API_URL` یا fallback توسعه).
- آدرس کامل `/api/v1/health`، کد وضعیت HTTP، تأخیر پاسخ و بدنهٔ JSON سلامت.
- پیام تفکیک‌کننده: خطای شبکه/آدرس در مقابل پاسخ سالم سرور، تا معلوم شود مشکل سمت گوشی/شبکه است یا سرور/حساب.

## ۴. اصلاحات تکمیلی دور دوم

پس از نصب APK پیشین سه ایراد باقی‌مانده پیدا و رفع شد:

| یافته | اثر روی گوشی | اصلاح |
|---|---|---|
| `I18nManager.allowRTL(false)` فقط پس از یک بار بستن و باز کردن اپ اثر می‌گذارد. | در **اولین اجرا** پس از نصب، گوشی فارسی هنوز همه‌چیز را آینه می‌کرد؛ همان علامت «لوگو سمت چپ». | ریشهٔ اپ علاوه بر پرچم‌های `I18nManager`، جهت خود Yoga را هم با `direction: 'ltr'` ثابت می‌کند؛ از همان اجرای اول یکدست است. |
| ماشین‌حساب کلیدها را با `I18nManager.isRTL` برعکس می‌کرد تا آینه‌شدگی سیستم را خنثی کند. | با ثابت‌شدن جهت ریشه، این برعکس‌سازی دوباره اعمال می‌شد و چیدمان کلیدها جابه‌جا می‌شد. | برعکس‌سازی حذف شد؛ کلیدها همیشه به ترتیب طبیعی خود رندر می‌شوند. |
| صفحهٔ خانه برای کاربر مهمان هیچ دکمهٔ ورود/ثبت‌نامی نداشت؛ تنها راه، آواتار → پروفایل → ورود بود. | کاربر مهمان عملاً «ثبت‌نام» را در برنامه نمی‌دید. | دکمهٔ «ورود / ثبت‌نام» در سربرگ خانه (فقط برای مهمان) اضافه شد و مستقیم به صفحهٔ ورود/ثبت‌نام می‌رود. |
| `authLimiter` فقط ۱۰ درخواست در ۱۵ دقیقه برای **هر IP** اجازه می‌داد و `refresh`/`logout` هم در همین سهم بود. اپ در هر اجرا یک refresh می‌فرستد و مشترکان موبایل پشت NAT اپراتور یک IP مشترک دارند. | پس از چند بار باز کردن اپ، پاسخ ۴۲۹ می‌آمد و ورود «انجام نمی‌شد» بدون اینکه رمز یا سرور مشکلی داشته باشد. | `sessionLimiter` جداگانه (۱۲۰ در ۱۵ دقیقه) برای `refresh`/`logout` و سهم ورود/ثبت‌نام به ۳۰ رسید؛ قفل حساب پس از ۵ تلاش نادرست (`AUTH.MAX_FAILED`) بدون تغییر باقی است. |

نسخهٔ اپ برای این ساخت به `1.0.1` و `versionCode` به `2` ارتقا یافت تا نصب نسخهٔ جدید روی نسخهٔ قبلی قابل تفکیک باشد.

## ۵. محدودیت‌های اعلام‌شده

- ساخت APK در این محیط انجام نشد؛ گردش‌کار `.github/workflows/build-apk.yml` با push روی `main` و تغییرات `mobile/**` اجرا و APK را به‌عنوان artifact آپلود می‌کند (نیازمند secret `EXPO_PUBLIC_API_URL`).
- تست زندهٔ ورود/ثبت‌نام روی دستگاه و دیتابیس واقعی انجام نشد؛ فقط مسیر کد، typecheck و باندل تأیید شده است.
- بخش‌های دانشی (استانداردها، ایمنی، فرصت‌ها) محتوای مرجع محلی دارند؛ فهرست زندهٔ آگهی‌ها و گفتگوی چندکاربره به سرویس سرور نیاز دارد و در UI همین محدودیت نوشته شده است.
- پرداخت قبض محاسبه و راهنما دارد؛ اتصال به درگاه بانکی در این نسخه فعال نیست و در صفحه نیز صریح اعلام شده است.
