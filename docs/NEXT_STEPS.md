# ترتیب ادامهٔ توسعه

## مرحلهٔ آماده‌سازی محیط

1. تنظیم `SENTRY_AUTH_TOKEN` فقط‌خواندنی، `SENTRY_ORG` و `SENTRY_PROJECT` در محیط محلی؛ سپس بررسی Issue/Eventهای واقعی.
2. فراهم‌کردن دسترسی مخزن GitHub (owner/repository)؛ ایجاد branch جداگانه و PR برای تغییرات ممیزی‌شده.
3. نصب وابستگی‌ها و اجرای `prisma validate`, `prisma generate`, تست فرانت‌اند، build وب و Expo typecheck/build.
4. اجرای migration فقط روی clone/staging پس از backup و بررسی drift؛ هیچ migration روی production بدون تأیید کاربر اجرا نشود.
5. اتصال DSNهای Sentry برای Backend و Mobile، انتشار نسخهٔ آزمایشی و بررسی Crash/Performance.

## مرحلهٔ محصول

1. تکمیل feed و گفت‌وگوی همکاران؛ کارت Home باید از دادهٔ واقعی شامل نام، عنوان شغلی، شهر و موضوع همکار تغذیه شود.
2. تکمیل ایمنی و آموزش و پنل مدیریت محتوا.
3. تکمیل ماشین‌حساب‌های مهندسی فقط با فرمول و منبع صفحه‌دار تأییدشده.
4. تکمیل محاسبه/پرداخت قبض فقط پس از دریافت تعرفه‌ها و فرمول‌های قطعی کاربر.
5. تکمیل مناقصات، بازار تجهیزات، آگهی‌های کاری و فرم‌های سازمانی.
6. افزودن فونت و assetهای نهایی موبایل، حریم خصوصی، شرایط استفاده و مدارک انتشار فروشگاهی.

## مرز اختیار

تحلیل، اصلاح کد در branch جداگانه و اجرای تست مجاز است. Merge، انتشار، تغییرات مخرب دیتابیس یا حذف دادهٔ کاربران نیازمند تأیید صریح کاربر است.
