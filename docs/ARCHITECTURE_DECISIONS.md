# هندبوک توزیع — تصمیم‌های معماری

## تصمیم‌های تأییدشده
- بک‌اند فعلی Express و پنل React حفظ می‌شوند؛ اصلاح‌ها افزایشی و سازگار با مسیرهای قدیمی هستند.
- API موبایل با پیشوند `/api/v1` توسعه می‌یابد؛ مسیرهای `/api` برای پنل وب و سازگاری نسخهٔ موجود باقی می‌مانند.
- معماری بک‌اند در شروع Modular Monolith است؛ هر ماژول مرز، قرارداد، اعتبارسنجی، مجوز و تست مستقل دارد.
- PostgreSQL پایگاه دادهٔ اصلی است.
- دیتاسنتر فایل از سرور API جداست؛ فایل‌ها در Object Storage، فراداده در PostgreSQL، فایل اصلی در سرویس ذخیره‌سازی مستقل روی دیسک پایدار/NAS و ایندکس در موتور جستجوی مستقل نگهداری می‌شوند. آداپتر S3-compatible می‌تواند جایگزین لایه فایل بدون تغییر API شود.
- SQLite رمزگذاری‌شده پایگاه دادهٔ محلی دائمی اپلیکیشن موبایل است؛ تاریخچهٔ ماشین‌حساب عمومی، دفترچه، پیش‌نویس فرم‌ها، کش جستجو و صف OCR در آن نگهداری می‌شوند.
- Refresh Token موبایل در SecureStore و Access Token فقط در حافظه نگهداری می‌شود؛ `tokenVersion` امکان ابطال Access Tokenهای قدیمی پس از تغییر نقش/سمت/وضعیت/رمز را فراهم می‌کند.
- عملیات آفلاین در Outbox محلی با شناسهٔ idempotency ذخیره می‌شود و پس از اتصال همگام می‌شود.
- OCR و ایندکس‌گذاری در پردازش پس‌زمینه اجرا می‌شوند، نه در مسیر پاسخ فوری جستجو. OCR موبایل ابتدا تصویر را در فضای پایدار اپلیکیشن ذخیره می‌کند و سپس در صف همگام‌سازی ارسال می‌کند.
- تعرفه‌ها و فرمول‌های قبض تا زمان دریافت نسخهٔ نهایی تأییدشده از مالک محصول وارد محاسبات عملیاتی نمی‌شوند.

## اصول توسعه ماژول
1. هیچ ماژولی نباید به فایل داخلی ماژول دیگر import مستقیم داشته باشد.
2. ارتباط بین ماژول‌ها از طریق قرارداد عمومی یا رویدادهای نسخه‌بندی‌شده انجام می‌شود.
3. فقط ماژولی بارگذاری می‌شود که `module.json` معتبر و `enabled: true` داشته باشد؛ فایل‌های غیرفعال import یا اجرا نمی‌شوند. افزودن ماژول به تغییر Router مرکزی نیاز ندارد.
4. هر تغییر دیتابیس Migration افزایشی و قابل بازبینی دارد.
5. حذف دادهٔ تاریخی ممنوع است مگر با برنامهٔ مهاجرت و پشتیبان قابل بازیابی.
6. فعال‌سازی قابلیت جدید با Feature Flag و تست رگرسیون انجام می‌شود.
7. APIهای فهرستی باید محدودیت اندازه صفحه و Cursor داشته باشند.
8. هیچ سند حجیمی به‌صورت پیش‌فرض روی موبایل دانلود نمی‌شود.

## مرزبندی ذخیره‌سازی
- PostgreSQL: هویت، نقش‌ها، مجوزها، فراداده، وضعیت عملیات و روابط.
- سرویس ذخیره‌سازی مستقل: PDF، تصویر و فایل اصلی روی Volume پایدار؛ در این نسخه پیاده‌سازی HTTP داخلی با Range و token دارد.
- Search Engine: OpenSearch برای ایندکس متن و فراداده، Cursor و فیلترهای نوع/زبان/تاریخ.
- Redis: کش ۳۰ ثانیه‌ای نتایج جستجو و کش ۱۰ ثانیه‌ای وضعیت مجوز کاربر؛ نتایج قبل از پاسخ دوباره با مجوزهای PostgreSQL فیلتر می‌شوند. Redis منبع حقیقت نیست.
- SQLite: دادهٔ محلی، کش کنترل‌شده، پیش‌نویس‌ها و Outbox.
